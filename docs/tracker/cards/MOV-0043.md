## Why this exists

Moving already uploads useful media, but a successful provider PUT does not
prove the bytes are the declared image or that every version can later be
found and removed. Convex must own that truth.

## Current truth

Upload sessions and B2-backed records exist. Current finish checks do not yet
prove the entire family contract: required authoritative SHA-256, full decode
before commit, exact provider version pinning, and all-version cleanup.

## Next safe action

Under Ready MOV-WO-011, upgrade the existing control plane rather than building
a new store. Bind operation ID, expected hash/size/type, move target, role,
source, visibility, and metadata fingerprint; verify exact stored bytes; pin
original/derivative versions; and make expiry/delete cleanup complete.

## Definition of done

- [ ] Same operation/fingerprint replays and changed input conflicts.
- [ ] Finish verifies server-required length/hash/type and full image decode.
- [ ] Every original/derivative records its exact provider version and digest.
- [ ] Cross-owner/move/target actions fail without existence leakage.
- [ ] Expiry/delete removes all versions, sessions, receipts, and product rows.

## Constraints

Extend the current upload/media system. Do not introduce another provider path,
trust client derivatives, expose object keys/URLs, or make storage possession
an authorization signal.

## Completion evidence

Not started. Existing uploads are foundation evidence, not proof of this
stronger finish and lifecycle contract.
